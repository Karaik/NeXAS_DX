# 七角色可装备变体：实施边界与第一批

目标继续是除Sou外九角色的实际操作特色。已有Freja/Yuri第一批与共通计数恢复不代表目标完成。此任务保留现有pipeline/DTO/Customizer架构，通过复制同角色现有武装、修改明确阶段行为形成装备选择，不创建新的角色方案语言或框架。

## 公共复制能力（先测试后实现）

允许在既有followup/customize包添加一个小型CharacterWeaponVariants工具（或在现有ProtectedCharacterEdits中补同等有限能力）；主代理持有pipeline、Importer、Runner编辑权，角色代理不得自行改这些文件。

必须遵守：

- 只复制已重绑的本角色主WAZ技能与MEK武装；所有外部依赖已经由原主WAZ声明，不导入新的跨角色/公共资源。
- 使用现有Jackson DTO多态深复制技能、使用独立武装对象和Material int[]副本，不使用已知会浅共享collection的Bean复制来复制技能。
- 通过MEK日英/第二标识和WAZ日英双名+真实引用唯一定位，原裸group/skill仅作源签名取证。
- 新普通武装使用新日文weaponName，保留其源weaponSequence与分类/标志语义，WAZ新英文身份使用明确DX_前缀；不发明新的武装属性或扩大153 bank。
- 新武装号只在当前连续MEK map末尾追加，实际可操作号必须<=152；不删除/重排原武装或AI引用。
- Material必须对应原武装行，必要时合并明确退出武装/供体的资源；三个group列表深复制。regularEntries/trailingEntries/entries三视图一致更新，不能只改其中一份。
- 验证源角色不是KOU三等级Material布局，尾表与现有武装消费关系匹配才追加；不套用Sou等级逻辑。
- 新技能通过最终MEK的wazFileSequence定位当前角色group；跳转目标按现有/复制技能身份定位后的最终skill index写入，不能写19/14/15等源裸索引。
- 整批验证结束才追加武装/技能/material；版本漂移、名字重复、尾表不匹配应拒绝且原对象不变。
- 重复执行不重复追加或累加改动；已存在变体必须与预期身份/载荷一致，不能仅发现同名就宣布成功。
- 复制后数目同步由主代理在现有pipeline定制之后再执行既有WazaGroup数量与Material padding方法；不新建顶层阶段架构。

先写源真实资源转换后的深复制/Material/幂等/拒绝半写测试，通知主代理串行Maven RED，然后实施。生成重解析使用JUnit临时目录，不写原版或共享JSON。任何API难以表达原生语义的地方回报具体问题，不能用删技能或提高全体伤害代替。

# 原生机体加载器容量校准

本项与地狱入口455BEE的配置选择越界分别处理。入口闪退由恢复已有Sou与114行运行表修复；这里解决CMekaLoader仍按103项分配、访问内联数组的问题。

## 结构与原生消费者

实际索引是MekaGroup机体ID，不是武装号或可见菜单格位。原版对象964字节：前132字节为线程、费用vector、锁、event和两个队列；随后是103项引用计数、103项状态、4字节累计费用、1字节活动标志和对齐padding。refcount[103]会落入state[0]，state[103]会覆盖累计费用，state[104]会覆盖活动标志，state[105]已越过分配。

容量N的布局为：引用数组起点132；状态起点132+4N；费用字段132+8N；活动位136+8N；总分配140+8N。N=114时分别是132、588、1044、1048、1052。构造器循环计数114，反向引用位移-456；预算扫描反向基址-588。

从真实PE闭环核对38个位点：16个状态位移、11个费用位移、6个活动位、扫描反向基址、扫描计数、构造计数、构造反向位移和唯一分配大小。析构为465960→4649C0→4646A0；内联数组是普通整数，无sized-free，析构／EH只额外销毁未移动的前缀子对象。引用数组的三个132位移保持原值。

## 实现边界

`MekaLoaderLayoutPatches`集中37个新增完整指令补丁，包含操作码和相邻立即数。已有两个BHE profile继续单独持有063A85的扫描上限，避免重复拥有或重叠。未知指令／未知中间布局会拒绝，已是目标字节则允许重复应用。保持原线程、队列、100MiB阈值与CRT链。

保留JINKI V2及旧实现基线：它们把机体表／扫描上限扩到104，但loader布局仍为103。因此BHE首层只识别该已知继承形状，迁移103布局至105；随后Followup按105→106直到114逐级扩展。不能用旧混合布局的中间产物继续代替全链重建。

## 定向验证

root先实际执行最小RED，1项失败、0错误；分配964／状态544／费用956／活动960／计数103／间距-412均与114项要求不符。实现后原生布局5项与CRT保留1项通过。

回归读取真实EXE，在内存保留未改V2阶段，再应用BHE逐层profile；按独立字面布局解码执行真实构造器清零指令，检查整个前缀、所有数组格、padding及尾canary。验证ID102/103/104/113的引用与状态不别名，不触费用或活动位；核对所有38个原生operand及原CRT字节。

另由生产`ApplyExePatchStep`执行3项验证：重复应用字节一致，损坏LEA操作码拒绝，未知104项中间布局拒绝。失败不发布EXE，源及临时输入SHA256保持，生成均在JUnit临时目录。与前述及地图冲突回归合计10项，失败／错误／跳过为0。

## 尚未解决的费用表

原`BQMekaMemory.dat`只有103行；原SHA256为`e4ba320cd2d6b1061d8d286228a450b0938a62bc748ceb88feafa98ad77b4bac`，420字节，单列int。构造器动态读取至EOF。4645E0、464CF0、465160仍会检查机体ID小于费用vector长度，单修对象布局不能保证新增机体异步加载安全。

费用是预计算的resident／预加载预算权重；load完成后加，最后引用释放并排队卸载时减，100MiB以上停止后台预加载。464630只汇总表值，不计算纹理成本。原103行中33项不是4的倍数，所以不能把它直接等同于纯RGBA纹理字节和。原有零值、自动伴随加载与共享资源也须保留。

当前未找到可信的新增费用计算公式，没有填0、随意复制donor费用、关闭长度检查或修改阈值。本项结论仅是固定对象布局校准；费用输出和实际加载验收继续进行，不能把本测试通过写成整个loader或九角色已经实机通过。094119入口测试包仍是修改前loader，不能充当本布局补丁的实机证据。

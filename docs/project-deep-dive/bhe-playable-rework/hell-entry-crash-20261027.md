# 地狱模式入口闪退取证

## 已确认的触发与原因

用户确认游戏窗口可见，从主菜单进入地狱模式即退出，尚未进入角色／关卡选择。先前黑色截图不能用来判定游戏画面本身全黑；等待肉眼反馈的阻塞已解除。

035924九角色包的机体容量为113，有效ID为0..112。原配置保留的上次地狱机体ID为113，对应已有Sou。九角色入口错误地跳过整个Sou构建阶段，造成配置与最终运行表不一致。计划原文要求“排除Sou的角色重做，保留Sou现有实现”，因此应恢复原有Sou阶段，而非清除用户选择或改写存档。

## Config结构复核

原Save与独立兼容seed的Config.dat SHA256均为`dcd523b050e71919d69c26bc836f5911866777893d4c415642ce3064a3e55884`。主压缩块文件偏移`0x4C9`，解压后1,024,808字节，版本19692。

- 主块`0x422C`的上次地狱机体ID为113。
- `0x4438`统计表字节数19152，等于114×168，连续五份。
- 运行记录从`0x6805C`开始，共114条；每条为4224固定字节、DWORD长度512、两段512字节，共5252字节。尾项数0位于`0xFA324`，EOF=`0xFA328`。
- 容量113的读取器在复制含选择113的主体之后，因19152大于18984拒绝统计表。私有case随后写成113行，但仍保存选择113；不能把它作为新兼容seed。

正确复测继续使用保全的114行seed，原Save保持只读。Script.dat已解析201条脚本记录，地狱变量表为空，未发现113；不能把最近一次Script写入当作原因。

## 修复和验证边界

九角色入口恢复运行原有Sou阶段，构建记录分别列出九个重做角色和保留的Sou。Sou专属机制不在本轮重做。

恢复完整链后，最终封包暴露既有直接地图SPM物化问题：`bhe_mapB6_ES02_ob01.spm`仍是BHE字节，BSDX解析在5561处失败。需要在直接资源物化时复用已有BHE→BSDX SPM转换器，多SPM组合路径保持既有处理，不能跳过最终验证。

另已发现CMekaLoader固定数组及BQMekaMemory行数仍以103为边界；这是后续加载的独立风险，不在本次455BEE栈上。需完成布局和费用消费者取证后独立处理。

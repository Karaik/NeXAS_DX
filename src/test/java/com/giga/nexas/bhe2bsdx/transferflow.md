# BHE -> BSDX Transfer Flow (Tsukuyomi baseline)

This document is a detailed, step-by-step description of the current BHE to BSDX transfer pipeline
implemented in `src/test/java/com/giga/nexas/bhe2bsdx/TransferTest.java` and the `steps/` package.
It focuses on the Tsukuyomi baseline case and lists the concrete files involved, their relations,
and how each step transforms or aligns data.

---

## 0. Scope and goal

The goal of this pipeline is to take a single BHE character (Tsukuyomi) and migrate its assets
to the BSDX format while keeping gameplay meaning intact. This includes:

- Core character data (`mek`)
- Skill data (`waz`)
- Sprite/animation data (`spm`, including hitbox pages)
- Registration tables (`grp`) that map indices to files
- UI references for pilot and selection screens (replacing an existing slot for testing)
- Static assets (images and voice files) copied into the output root

The pipeline is **not** a full-game migration. It only migrates the selected character and the
explicitly updated registries.

## 2. Data relationships (how files reference each other)

These relationships must stay consistent after migration:

- `grp/mekagroup.grp` provides the **index** for a character (`mekaCodeName`), used by UI and other tables.
- `grp/wazagroup.grp` provides the **index** for skills (`wazaCodeName` and `wazaDisplayName`).
- `grp/spritegroup.grp` provides the **index** for battle `spm` files (`spriteFileName`).
- `MekBasicInfo.wazFileSequence` must match the final index in `wazagroup.grp`.
- `MekBasicInfo.spmFileSequence` must match the final index in `spritegroup.grp`.
- `MekMaterialBlock.spriteGroups` stores spritegroup indices referenced by skills/animations.
- `batvoice.grp` stores voice file references; `MekVoiceInfo` uses `groupId` to refer to batvoice groups
  (full verification is still pending).
- `Spm.imageData[].imageName` stores static image file names (these must exist as files on disk).

## 3. Text flowchart (high level)

```text
[BHE binary assets]
  - grp: batvoice/mekagroup/wazagroup/spritegroup
  - mek/waz/spm: tsukuyomi + c_/g_/m_/s_ UI spm
            |
            v
[TransferTest#testPipeline]
  - parse BHE + BSDX resources (windows-31j)
  - select Tsukuyomi baseline
            |
            v
[TransMeka.process]  (Step0..Step6 in TransMekaPipeline)
  Step1  batvoice deep copy + append to BSDX
  Step2  grp upsert (meka/waza/sprite) and return indices
  Step3  spritegroup mapping (BHE -> BSDX)
  Step4  convert mek/waz/spm (includes hitbox)
  Step5  align MekBasicInfo waz/spm indices
  Step6  UI spm replacement (Nanoha slot -> Tsukuyomi)
            |
            v
[TransMekaResult]
  - converted mek/waz/spm (incl. c/s/g/m)
  - UI spm updates
  - group indices and sprite map
            |
            v
[Output + Assets]
  - write changed grp/mek/waz/spm to testBhe
  - copy static assets into testBhe root
  - attempt pac pack (PacUtil.pack)
```

## 4. Detailed step-by-step flow (matching code)

### Step 0: Build request
Code: `src/test/java/com/giga/nexas/bhe2bsdx/steps/TransMeka.java`

- `TransMeka.process(...)` converts the old argument list into a single `TransMekaRequest`.
- This wraps all BHE source data and BSDX target registries into one object.
- It avoids touching call sites when the pipeline is refactored.

Files involved:

- BHE: `tsukuyomi.mek`, `tsukuyomi.waz`, `tsukuyomi.spm`, `c_/g_/m_/s_` spm
- BHE grp entries for Tsukuyomi in `mekagroup.grp`, `wazagroup.grp`, `spritegroup.grp`
- BHE batvoice group from `batvoice.grp` (index `1` for this test)
- BSDX registries: `mekagroup.grp`, `wazagroup.grp`, `spritegroup.grp`, `batvoice.grp`
- BSDX UI spm: `mekapilot.spm`, `selectmekamenumeka.spm`
- BSDX dat: `SelectMekaMenu.dat`

---

### Step 1: BatVoice deep copy and append
Code: `src/test/java/com/giga/nexas/bhe2bsdx/steps/BatVoiceConverter.java`

- Converts `BHE BatVoiceGroup` -> `BSDX BatVoiceGroup`.
- `existFlag` is normalized to `1` if null.
- Voice entries are deep-copied to avoid mixed BHE/BSDX types.
- Result is appended to BSDX `batvoice.grp`, and the new index is recorded.

Why this matters:

- `MekVoiceInfo` uses `groupId` to select a voice group; the new index is required
  so the correct voices can be located.

---

### Step 2: grp alignment (meka/waza/sprite)
Code: `src/test/java/com/giga/nexas/bhe2bsdx/steps/GrpRegistryUpdater.java`

For each registry:

- **mekagroup**: match by `mekaCodeName`; if not found, use empty slot or append.
- **wazagroup**: match by `wazaCodeName` or `wazaDisplayName`; otherwise insert.
- **spritegroup**: match by `spriteCodeName` or `spriteFileName`; otherwise insert.

Output:

- `mekaGroupIndex`, `wazaGroupIndex`, `spriteGroupIndex`
- These indices are used later to align `MekBasicInfo`.

Relationship enforced:

- `MekBasicInfo.wazFileSequence` == `wazagroup` index
- `MekBasicInfo.spmFileSequence` == `spritegroup` index

---

### Step 3: spritegroup index mapping (BHE -> BSDX)
Code: `src/test/java/com/giga/nexas/bhe2bsdx/steps/SpriteGroupIndexMapper.java`

Purpose:

- BHE `MekMaterialBlock.spriteGroups` reference BHE spritegroup indices.
- BSDX spritegroup indices can be different (due to insertion or gaps).

Process:

1. Collect all spritegroup indices actually referenced by the BHE Mek material block.
2. For each referenced index:
   - Read the entry from BHE `spritegroup.grp`.
   - Ensure that entry exists in BSDX `spritegroup.grp` via upsert.
3. Build a map `{bheIndex -> bsdxIndex}` for only the required indices.

Output:

- `spriteIndexMap` used in `MekMaterialConverter`.

---

### Step 4: Convert core assets (mek/waz/spm)
This step produces converted BSDX objects for Tsukuyomi.

#### 4.1 Mek conversion
Code: `src/test/java/com/giga/nexas/bhe2bsdx/steps/MekConverter.java`

Sub-steps:

- Copy `MekHead` (offset table).
- Copy `MekBlocks` (block sizes).
- Copy `MekBasicInfo` (bulk property copy).
- Copy `MekPairBlock` (list of pairs).
- Copy `MekWeaponInfoMap` (drops BHE-only fields).
- Convert AI events via `MekAiConverter`.
- Convert voice tables via `MekVoiceConverter`.
- Convert material block via `MekMaterialConverter`.

Key notes:

- `MekAiConverter` deep-copies CPU events and sets BSDX-only fields such as `int26`.
- `MekVoiceConverter` preserves voice version and deep-copies emotion/slot tables.
- `MekMaterialConverter` currently clears sprite/se/voice groups (see below).

#### 4.2 Material block conversion
Code: `src/test/java/com/giga/nexas/bhe2bsdx/steps/MekMaterialConverter.java`

Current behavior:

- `CLEAR_MATERIAL_GROUPS = true`
- The converter keeps the **group counts** but clears group contents to avoid
  incorrect references during early testing.

If enabled later:

- BHE `spriteGroups` are pairs; BSDX keeps only the first value.
- `spriteIndexMap` remaps BHE indices to BSDX indices.

#### 4.3 Waz conversion
Code: `src/test/java/com/giga/nexas/bhe2bsdx/steps/WazConverter.java`

Key logic:

- BHE has 83 slots; BSDX has 72.
- Slot mapping table converts BHE slot -> BSDX slot; unmapped slots are dropped.
- Special handling for slot 37:
  - BHE `CEventFreeParam` -> BSDX `CEventVal`
  - Extracts the buffer 0 value and maps fields.
- Default frame data is normalized where required to avoid nulls.

Expected side effect:

- Some BHE-only events are dropped (e.g., slot 23, slot 52).

#### 4.4 Spm conversion
Code: `src/test/java/com/giga/nexas/bhe2bsdx/steps/SpmConverter.java`

Scope:

- Converts the main battle `tsukuyomi.spm` **and** UI spm (`c_`, `g_`, `m_`, `s_`).

Logic:

- Copy top-level spm properties.
- Rebuild `imageData`, `animData`, and `pageData` lists.
- Normalize sizes and counts (`numPageData`, `numImageData`, `numAnimData`).
- Convert `chipData` rectangles to BSDX rects.
- Convert `hitRects` by calling `BHE SPMHitArea.transHitbox()` and filling defaults:
  - `unk0` from shape mapping
  - `unk1`/`unk2` for z-range
- Build `hitFlag` as a bitset from hitRect count.

---

### Step 5: Align MekBasicInfo indices
Code: `src/test/java/com/giga/nexas/bhe2bsdx/steps/TransMekaPipeline.java`

Actions:

- `MekBasicInfo.wazFileSequence = wazaGroupIndex`
- `MekBasicInfo.spmFileSequence = spriteGroupIndex`

This ties the converted `mek` to the correct `waz` and `spm` entries in BSDX registries.

---

### Step 6: UI SPM replacement (test strategy)
Code: `src/test/java/com/giga/nexas/bhe2bsdx/steps/UiSpmReplacer.java`

Goal:

- For testing, replace the existing Nanoha slot with Tsukuyomi data
  instead of appending a new slot.

#### 6.1 MekaPilot.spm
- Find the animation index by `TARGET_PILOT_NAME` (constant in `UiSpmReplacer`).
- Collect page indices used by that animation.
- Replace those pages with pages from `m_tsukuyomi.spm`.
- Replace the image name at the target image index with the first image from `m_tsukuyomi`.
- Update `animName` to Tsukuyomi pilot name (from `MekBasicInfo`).

#### 6.2 SelectMekaMenuMeka.spm
- Find the Nanoha meka index in `mekagroup.grp` using `TARGET_MEKA_CODE`.
- Map that meka index to a UI anim index using `SelectMekaMenu.dat`.
- Replace pages with `s_tsukuyomi.spm` (same logic as above).
- Replace the image name at the target image index with the first image from `s_tsukuyomi`.
- Update the animation name to the Tsukuyomi menu name.

Notes:

- This is a temporary test strategy. It allows immediate validation without
  adding a new UI slot.

## 5. Writing outputs (binary)
Code: `src/test/java/com/giga/nexas/bhe2bsdx/steps/TransMekaOutputWriter.java`

Process:

- Writes only the **changed** resources to the output directory.
- Output subdirectories:
  - `grp/`
  - `mek/`
  - `waz/`
  - `spm/`
- Uses `BsdxBinService.generate(...)` with `windows-31j` encoding.

The following outputs are generated in the Tsukuyomi run:

- `grp/batvoice.grp` (with appended group)
- `grp/mekagroup.grp`
- `grp/wazagroup.grp`
- `grp/spritegroup.grp`
- `mek/tsukuyomi.mek`
- `waz/tsukuyomi.waz`
- `spm/tsukuyomi.spm`
- `spm/c_tsukuyomi.spm`
- `spm/s_tsukuyomi.spm`
- `spm/g_tsukuyomi.spm`
- `spm/m_tsukuyomi.spm`
- `spm/mekapilot.spm` (if UI replacement succeeds)
- `spm/selectmekamenumeka.spm` (if UI replacement succeeds)

## 6. Static asset copying
Code: `src/test/java/com/giga/nexas/bhe2bsdx/steps/StaticAssetCopier.java`

What is collected:

- From each output `spm`: `imageData[].imageName`
- From `batvoice.grp`: `BatVoice.voiceFileName`
- (Optional) From `segroup.grp`: `SeGroupItem.seFileName` if a se grp is provided

How it works:

- Builds a case-insensitive index of all files under `STATIC_ASSET_ROOT`.
- Copies matching files into the output root directory.
- Logs missing assets and duplicates.

Important constraints:

- Files are copied directly into `src/main/resources/testBhe/` (no subfolders).
- Only spm images and batvoice files are currently passed in.
- If you want segroup assets, you must pass a `SeGroupGrp` into the asset map.

## 9. Known limitations (current state)

These are not part of the flow but are important for accuracy checks:

- `MekMaterialBlock` sprite/se/voice groups are cleared by default.
- Some BHE WAZ slots are dropped due to 83 -> 72 mapping.
- `spritegroup` indices that do not map will keep the original BHE index.
- `PacUtil.pack` currently reports `Size:0`.
